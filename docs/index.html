The problem

Your branches shouldn’t fight over one folder.

Git worktrees solve parallel development. wtm gives that workflow the interface it deserves.

01

Parallel context

Keep a feature, hotfix, review, and experiment open at the same time. No stash gymnastics. No lost local state.

wtm add feature/payments
02

Instant signal

See dirty, ahead, behind, merged, gone, missing, locked, and prunable worktrees before you touch anything.

wtm list --json
03
✓

Safe cleanup

Dirty worktrees are protected, main is untouchable, and branch deletion always requires an explicit path.

wtm prune --merged --gone

Pick a flow

A better daily loop

From branch idea to clean exit.

wtm stays small on purpose. Each command does one useful thing, and the pieces compose naturally.

1

Spin up a context

Give a branch its own directory and optionally start from any ref.

wtm add feature/login
wtm add --from origin/main hotfix
2

Work without collisions

Open a worktree in your editor, run a command inside it, or switch there from your shell.

wtm open feature/login
wtm switch feature/login
3

Prune with a preview

Find stale worktrees, inspect the plan, and clean them while protected branches stay safe.

wtm prune --merged --gone --dry-run
wtm prune --merged --gone

Core commands

wtm add <branch>
Create a worktree and branch.

Show every registered worktree.

Configuration

Keep shared project defaults in .worktree.toml and machine-specific values in .worktree.local.toml.

path_template = "../{repo}-worktrees/{branch}"
default_base = "origin/main"
editor = "code"

[setup]
commands = ["npm install"]

[[setup.copy]]
path = ".env"
mode = "copy"
✓

Safety model

Your local work stays yours.

Dirty worktrees refuse removal unless --force is explicit. The main worktree and protected branches are never selected for cleanup. Branches are only deleted through an explicit remove or merged/gone prune.
