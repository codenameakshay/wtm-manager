## Why this matters

v0.9.0 made the desktop app the headline. That is the right human cockpit. It is not yet the thing agents actually *create and clean up* worktrees with.

This repo, right now, already has worktrees created by T3 Code (`~/.t3/worktrees/worktree-manager/t3code-*`) and a leftover Claude Code tree (`.claude/worktrees/codebase-slop-audit-*`, detached HEAD). `wtm list` discovers them — that part of the 0.1.0 bet still holds — but `wtm add` cannot express "give me a unique throwaway," mutating commands print English, `wtm prune --merged --gone` reported `nothing to prune` while those leftovers sat there, and `wtm path t3code` failed with a confusing ambiguous-match error.

The maintainer wants wtm to become the default worktree manager for every agentic workflow. v0.10.0 is the first release that treats agents as a first-class caller of the CLI, without replacing git's registry and without boiling the ocean (MCP, Windows, notarization).

## Three possible 0.10.0 shapes

**A. Polish-only.** Bugfixes from live use (`find` error, GUI cwd on remove, skill JSON drift) plus Homebrew/Fish. Lowest risk. Does **not** make agents prefer `wtm add` over raw `git worktree add`.

**B. Agent CLI contract (recommended).** A plus: unique create, `--json` on add/remove/prune, `head_time` on list, leftover/detached prune, smarter merged base, Cursor/AGENTS.md skill. This is the smallest cut that changes whether an agent would actually call wtm.

**C. Platform/app leap.** Notarization, MCP, Linux real-desktop pass, Windows, provenance database. Any one of these is a release by itself; stacking them on B slips the "slowly" constraint.

v0.10.0 is **B**. C becomes the 0.11+ backlog.

## Must land in 0.10.0

### 1. Fix worktree name resolution for agent ID prefixes

**Bug, verified live.** `find("t3code")` substring-matches registry name `t3code-bd91b00c` even though that row's display name is `akshay/close-the-loops`. The error is:

```
no worktree or branch named 't3code (ambiguous: matches akshay/close-the-loops, t3code/2b5af0c6)'
```

Two defects:

1. Substring match on the hidden git registry name (T3/Cursor IDs share prefixes constantly).
2. `Error::WorktreeNotFound(format!(…))` stuffs the hint into the `{0}` of `no worktree or branch named '{0}'` (`src/error.rs:17`, `src/worktree.rs:105-107`).

**Fix sketch:**

- Exact match order stays: registry `name`, then `branch`.
- Substring match **display_name only** (branch, or registry name when detached). Do not substring-match a registry name the user never saw.
- New error variant or a dedicated Display: `no worktree named 't3code' (ambiguous: …)` — do not nest the hint inside the quoted name.
- Update `src/worktree.rs` tests `find_resolves_name_branch_and_unique_substring` / `find_rejects_ambiguous_and_unknown_names`. Add a case with registry name `t3code-aaaa` / branch `other/topic` that must **not** match query `t3code` if another `t3code-bbbb` exists, and must not match via the hidden registry id when the user-facing branch does not contain the needle.

**Files:** `src/worktree.rs`, `src/error.rs`, tests in `src/worktree.rs`.

### 2. `wtm add --unique` / `--detach` — throwaway create

Agents (and Cursor/T3) create uniquely named worktrees. Today `AddArgs.branch` is required and `BranchInUse` aborts (`src/commands/add.rs:109-119`). `gitcmd` cannot pass `--detach`.

**Fix sketch:**

- `wtm add --unique [stem]` — if `stem` omitted, use `wtm`. Generate `stem/<8 hex>` (or `stem-<8 hex>` if stem has no slash preference — pick **one** and document it). Recommended: `wtm/<hex>` to sit next to existing `cursor/<id>` and `t3code/<id>` in the list. Retry on collision.
- `wtm add --detach [name]` — `git worktree add --detach <path> <base>`. Optional registry-friendly name via `--path`. Detached trees are what Claude Code already left in `.claude/worktrees/`.
- Do **not** auto-suffix on `BranchInUse` without a flag (GUI shares `create_core`).
- Prefer `--unique` as the agent default in the skill; `--detach` is available for tools that do not want a branch to clean up.

**Files:** `src/cli.rs`, `src/gitcmd.rs`, `src/commands/add.rs`, `tests/cli_lifecycle.rs`, `DESIGN.md`, skill.

GUI/TUI: a "unique" checkbox in New Worktree is nice but **not** required for 0.10 if time is tight. CLI first.

### 3. `--json` on add / remove / prune

`DESIGN.md:384` currently forbids this. 0.10 updates the contract.

Default human stdout stays. `--json` prints one object to stdout; git/setup chatter goes to stderr (or requires `--quiet`).

Shapes (lock these in `tests/cli_json.rs`):

```json
// wtm add --json [--unique]
{ "ok": true, "action": "add", "name": "wtm/a1b2c3d4", "branch": "wtm/a1b2c3d4", "path": "/abs/path", "detached": false }

// wtm remove --json foo
{ "ok": true, "action": "remove", "name": "foo", "path": "/abs/path", "branch_deleted": false }

// wtm prune --json --merged --gone
{ "ok": true, "action": "prune", "removed": 2, "skipped": ["dirty-one"], "failures": [], "candidates": ["a", "b"] }
```

`--json` on failure: still exit 1, still `error: …` on stderr for 0.10 (do not invent an error envelope yet). Dry-run prune with `--json` sets `removed: 0` and fills `candidates`.

**Files:** `src/cli.rs`, `src/commands/{add,remove,prune}.rs`, `tests/cli_json.rs`, `DESIGN.md`, `skills/wtm/reference.md`.

### 4. `head_time` on `wtm list --json`

GUI already computes this (`data::worktree_activity`). CLI JSON cannot sort "reuse a recent worktree vs create." `head_info` already has the oid via the main repo (`src/worktree.rs:437-460`).

Keep `--fast` behavior: `status` remains null; `head_time` still present when the oid peels.

### 5. Prune leftovers agents actually leave behind

Verified: `wtm prune --merged --gone --dry-run` → `nothing to prune` while a detached Claude tree and a T3 tree on a merged PR sit on disk.

Two independent causes:

**a. Merged detection uses local main HEAD by default** (`Config.default_base: None`). This repo's main is `↑0 ↓37`. A branch merged on GitHub is not an ancestor of a stale local `main`, so `--merged` is blind until someone pulls. Sample config already comments `default_base = "origin/main"`.

Recommended 0.10 behavior when `default_base` is unset:

1. If `refs/remotes/origin/HEAD` or `origin/main` / `origin/master` resolves to a commit, use that.
2. Else main worktree HEAD (today's behavior).

Print the resolved base in `wtm prune --verbose` / `wtm list -v` so this is inspectable. Do **not** fetch implicitly inside `list` (network on a read path). Document `wtm fetch` before relying on `--gone` / behind counts. Optionally have the **app** Prune dialog show the resolved base name.

**b. Detached / nameless leftovers are never merged/gone candidates** (no branch). Add `wtm prune --detached` (and a matching Prune dialog toggle): include linked worktrees whose `branch` is `None`, that are not main, not locked, not protected. Still dirty-safe unless `--force`. Do not delete a branch (there isn't one).

Do **not** add `--older-than` in 0.10 unless 5a/5b land first. Age-based prune is 0.11 once `head_time` exists.

### 6. Stop the GUI inheriting the CLI cwd-remove guard

0.9.0 moved prune's cwd skip to CLI/TUI because "the GUI's process cwd is meaningless" (`DESIGN.md`, `CHANGELOG.md`). `remove_worktree` still checks `contains_cwd` (`src/commands/remove.rs:79-84`), and the GUI calls it (`crates/wtm-gui/src/data.rs:106-107`).

Launching `wtm` from inside a worktree (or `wtm-gui` on Linux from a terminal) can refuse Remove on that row.

**Fix:** same split as prune. `remove_worktree` drops the cwd check. CLI `remove::run` and TUI apply `contains_cwd` before calling it. GUI does not. Add a GUI integration test that remove succeeds even if process cwd is inside the target (set cwd in the test if feasible; otherwise a unit test on the core with a fake cwd is enough).

## Maintenance notes

- After 0.10, a thin MCP is a mechanical wrapper around `add --json` / `list --json` / `remove --json` / `prune --json`. Do not design MCP before those flags exist.

- Notarization and Homebrew are how humans install the daily driver; they do not replace the agent contract.
